毎日の自動計測を組んでください。データ集めは Claude を使わない普通のPythonスクリプトにし、PCの定期実行機能で毎日動かします。分析は人が必要なときに Claude Code で行います。

## 1. 何を毎日取るかをユーザーと決める
次の候補を示し、使うもの・使えるもの（権限やAPIキーがあるか）を確認する。
| 項目 | 取得方法 | 必要なもの |
|---|---|---|
| 両店の口コミ総数・評価 | Places API (New) の Place Details（rating, userRatingCount のみ） | Places APIキー（`/review-count` で設定済みなら流用） |
| 行列の長さ | カメラが自動で書き出すCSV、または自動保存される静止画フォルダを読む | カメラ／レコーダーに「定期スナップショット保存」か「人数カウントの書き出し」機能があること。無ければこの項目は保留 |
| 自店のマップでの表示回数・ウェブサイトクリック・ルート検索・電話 | Google Business Profile Performance API | 店舗プロフィールのオーナー権限とAPIの利用申請 |
| HPの言語別・国別アクセス、予約フォーム送信数 | GA4 Data API | GA4のプロパティIDとサービスアカウント |
| 検索の国別表示回数・英語キーワード | Search Console API | Search Console のプロパティとサービスアカウント |
各APIは、実装前に最新ドキュメントで仕様と料金・無料枠を確認し、要点をユーザーに伝える。権限が無いものは無理に進めず「保留」として一覧に残す。

## 2. `scripts/daily_collect.py` を作る
- 選んだ項目ごとに関数を分け、1つが失敗しても他は続ける。
- 結果は `data/daily/` に項目別CSVで追記（`date` 列必須、同じ日付の行が既にあれば上書き）。
  - `reviews.csv`: date, store, rating, review_count
  - `queue.csv`: date, timestamp, queue_length（カメラ。前日分の画像／CSVを処理。画像は人数を数えるだけで、切り抜きや加工画像は保存しない。処理済みの元画像の扱いは社内ルールに合わせてユーザーに確認）
  - `gbp.csv`, `ga4.csv`, `gsc.csv`: 各APIの指標
- 実行ログを `data/daily/run.log` に残す（APIキーは出さない）。
- 3日連続で失敗した項目があれば、ログの先頭に分かるように書く。
- まず手動で1回実行し、結果をユーザーに見せる。

## 3. 定期実行を登録する
- ユーザーのOSを確認する（macOS: launchd、Windows: タスクスケジューラ、Linux: cron）。
- 実行時刻は閉店後（例：19:30）を提案する。PCがその時刻に起動している必要があることを伝え、店のPCの電源が何時まで入っているか聞く。
- 登録内容（時刻・実行するコマンド・ログの場所）を見せ、了承を得てから登録する。
- 登録の確認方法と、止め方・削除の方法も書いて渡す。
- PCが常時起動していない場合の代案：口コミ総数だけなら GitHub Actions など、クラウドの定期実行でも動かせる（APIキーはシークレットに保存）。必要ならその設定も手伝う。

## 4. 見るためのコマンド
`scripts/daily_view.py` を作り、実行すると次を `output/daily_dashboard.png` と端末表示で出す：
- 口コミ総数の推移（両店）と、7日移動平均での1日あたり増加件数。「このペースで何日後に件数が並ぶか」（並ばなければそう表示）
- 行列の長さ：曜日×時間帯の平均（データがあれば）
- 施策を入れた日を `data/daily/events.csv`（date, event）に書いておけば、グラフに縦線で表示する。施策の前後比較ができるようにするため。

最後に、ユーザーが毎週やること（`daily_view.py` を見る、施策を入れたら events.csv に1行書く）を3行でまとめる。
